## 1. 二号任务边界

```python

    week, bmi_baseline, height, weight, age,
    thr=0.04, prev_week=None

```

并完成：

1. 多因素个体期望风险计算；

5. 个体分配、组内时点与达标概率输出；
6. 与问题二正式方案对照；
7. 风险参数、检测误差和概率模型变体的敏感性分析。

当前已取得一号的 `src/q3_model.py`。该模块通过 `load_prob_fn()` 返回上述概率函数；二号程序同时兼容模块顶层 `prob_qualified` 和 `load_prob_fn()` 两种入口。首次正式运行前需先执行一号脚本生成本地 `outputs/q3_model.npy`。模拟概率仍只用于程序联调，结果不会写入正式文件名。

## 2. 数据口径

主数据为 `data/processed/male_clean_event.csv`。按孕妇代码排序后，每位孕妇只保留首次检测时已经可知的：

- 基线BMI；
- 身高；
- 体重；
- 年龄。

同一孕妇复检时上述变量保持不变，只递进孕周。缺少任一必备变量的孕妇会在优化前被剔除并报告人数；现有数据完整时应得到267位孕妇。

分组变量仍为基线BMI，身高、体重和年龄只进入个体达标概率和个体风险，不直接作为分组边界。

## 3. 多因素风险递归

设第$i$位孕妇协变量为

$$
x_i=(b_i,h_i,w_i,a_i),
$$

一号接口给出

$$
p_i(t)=P\!\left(Y_i(t)\ge 0.04\mid x_i\right).
$$

若本次未达标，复检间隔、失联概率与延误风险函数继承问题二。第$i$位孕妇首次在$t$周检测的期望风险为

$$
E_i(t)=p_i(t)R(t)+[1-p_i(t)]
\left\{qR_{\mathrm{drop}}+(1-q)E_i(t+\Delta)\right\}.
$$

复检时再次调用一号接口，并传入 `prev_week`，以正确计算条件首次达标概率。程序会逐次检查概率有限且位于$[0,1]$内。

## 4. 精确连续分组

将267位孕妇按基线BMI升序排列。对所有允许的连续区间$[i,j)$和检测时点$t$，计算

$$
C(i,j)=\min_t\sum_{r=i}^{j-1}E_r(t).
$$

动态规划递推为

$$
D(k,j)=\min_i\left\{D(k-1,i)+C(i,j)\right\}.
$$

约束为：

- 扫描$k=1,ldots,6$；
- 每组至少15人；
- 边界只能位于相邻不同BMI值之间；
- 同一BMI不能被拆到两组；
- 每位孕妇恰好分配一次。

程序输出每个$k$的平均风险、相对不分组降幅、边际改善、精确边界、组人数和最佳孕周。

## 5. 组数选择

为了和问题二保持可比性，问题三沿用同一套显式判据，而不是硬编码组数：

1. 收益捕获率至少90%；
2. 相邻组推荐时点至少相差1周；
3. 每组至少15人。

取同时满足三条判据的最小$k$。因此问题三可能仍为3组，也可能因多因素概率改变而成为其他组数；必须运行后决定，不能直接复制问题二。

## 6. 整数边界优化

精确切点可能是29.858一类不便执行的小数。问题三不会简单逐个四舍五入，而是枚举BMI观测范围内所有可行的整数切点组合。

对于每组数$k$，从所有整数边界组合中筛除人数不足15人的方案，再重新计算每组最佳孕周和总风险，选择整数方案中的全局最优。报告

$$
\Delta R=R_{\text{integer}}-R_{\text{exact}},
$$

作为边界整数化代价。

### 6.1 当前正式方案

三条判据选出 $k=3$。整数边界全局搜索得到：

| BMI区间 | 人数 | 数学最优孕周 | 可执行时点 | 组内平均风险 |
|---|---:|---:|---:|---:|
| $[20.70,32)$ | 152 | 14.20 | 14周+1天 | 1.81905 |
| $[32,36)$ | 95 | 15.35 | 15周+2天 | 2.08263 |
| $[36,46.88]$ | 20 | 19.60 | 19周+4天 | 2.94285 |

总体平均风险为1.99701，整数化相对精确动态规划解增加约 $1.48\times10^{-4}$。推荐孕周进一步取整到最接近的整天后，总体风险约为1.99998，额外代价约0.00297。$k=3$已捕获91.36%的可达分组收益，且相邻组推荐时点最小相差1.25周；$k=2$未达到90%的收益捕获阈值，虽然$k=4$也满足判据，但规则要求选择同时满足判据的最小组数，因此最终选择3组。

## 8. 敏感性分析

`q3_sensitivity.py`已支持：

- 风险梯度$r_{mid}=2,3,5$；
- 失联概率$q=0.05,0.094,0.15$；
- 复检间隔$\Delta=3.14,3.70,4.14$周。

若一号模块额外提供

```python
probability_variants() -> dict[str, callable]
```

二号程序会自动对检测误差情景、参数蒙特卡洛抽样或模型权重情景重新执行完整动态规划，而不是只在固定边界上计算一次风险。

当前一号模块尚未提供 `probability_variants()`，因此概率变体仍需单独接入；参数蒙特卡洛已经由 `q3_sensitivity.py` 直接读取 `q3_model.npy` 的参数协方差，并对每次抽样重新执行完整动态规划。

二号另外直接读取一号导出的AFT参数协方差矩阵，进行100次固定随机种子的参数蒙特卡洛抽样；每次均重新计算267人的风险矩阵并重新执行组数判据、动态规划和整数边界搜索。结果中54%选择3组、20%选择4组、3%选择2组、23%没有任何组数同时满足三条判据；名义整数边界32/36出现34%。因此3组可作为点估计方案，但边界稳定性一般，论文中必须同时报告这一限制。该过程属于参数协方差蒙特卡洛，不应写成孕妇层面的非参数Bootstrap。

抽样逐次结果写入`q3_sensitivity.csv`，方案频率汇总写入`q3_boundary_stability.csv`。

若某个敏感性情景下没有任何 `k` 同时满足三条判据，程序不会强行指定组数，而是在 `status` 中记录 `no_feasible_k`，并在 `criterion_failures` 中逐个列出各 `k` 未通过的判据。该结果表示方案对该扰动不稳健，需要在论文中如实报告。

## 9. 验收检查

正式输出必须同时满足：

1. 每位孕妇恰好出现一次；
2. 各组人数之和等于纳入孕妇数；
3. 每组不少于15人；
4. BMI区间连续且不拆分相同BMI；
5. 最优平均风险随可选组数增加不升高；
6. 所有达标概率均在$[0,1]$内；
7. 正式结果不带 `mock` 标记；
8. `q3_vs_q2.csv`同时包含问题二和问题三结果。
9. 累计达标概率对全部267人均随孕周单调不减；
10. 条件概率与累计概率恒等式在12–24周检查点成立；
11. 敏感性基准情景精确复现正式边界和推荐孕周。

## 10. 运行方式

一号接口未提交时，只做联调：

```powershell
python src\q3_optimize.py --mock
python src\q3_sensitivity.py --mock
```

一号接口提交后，生成正式结果：

```powershell
python src\q3_optimize.py
python src\q3_sensitivity.py --parameter-draws 100 --seed 2026
```

参数蒙特卡洛默认抽样 100 次；调试时可减少次数：

```powershell
python src\q3_sensitivity.py --parameter-mc 10
```

如果一号使用自定义模块名：

```powershell
python src\q3_optimize.py --module q3_survival
python src\q3_sensitivity.py --module q3_survival
```
