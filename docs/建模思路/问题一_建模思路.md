## 4. 决策点

### 决策点 1：BMI 必须拆成 between（基线）/ within（孕期内变化）

- **现象**：BMI 是随孕周变化的时变协变量，但孕妇内 BMI 与孕周相关 r=+0.578（独立脚本验证，见下方"已验证的数字"），即体重随孕期增长，与孕周效应本身混杂。
- **处理**：`bmi_baseline` = 该孕妇首次抽血时的 BMI（Q2 分组要用的、调度时刻已知的量）；`bmi_within = bmi_ij - bmi_baseline`（孕期内相对基线的变化量）。
- **代码里的检验**：拟合"单一 bmi_c 系数"与"between/within 分开两个系数"两个模型，做 LRT，检验 H0: 两个系数相等（即朴素做法是否成立）。这一步在【部件2】。
- **对 Q2 的意义**：`predict_y`/`prob_qualified`/`week_reach` 现在的第二个参数是 `bmi_baseline`，不再是笼统的 "bmi"——这是本次修复最核心的一处接口变更。

### 决策点 2：孕周项从二次多项式换成自然三次样条

- **触发原因**：LOWESS（不预设函数形式的非参数平滑）显示孕周效应形状是"**11~15周快速上升 → 16~20周平台期 → 24~29周再加速**"，二次多项式（只能是单一开口方向的抛物线）结构性地拟合不出中段平台。
- **独立验证过的数字**（跑在一个游离于主脚本外的临时诊断脚本里，逻辑与主脚本一致）：样条(df=5) AIC 比二次多项式好约 20（决定性差距，ΔAIC>10 即为强证据）。
- **代码实现**：`WEEK_TERM = 'cr(week_c, df=5)'`，patsy 的自然三次样条基，`df=5` 在【部件3b】的 M1~M7 比较表中会和 df=4/6 以及二次多项式对照（当前代码固定用 df=5 作主设定，比较表里的 "M3q" 是二次多项式对照项）。
- **风险与代码里已做的防护**：样条外推极不可靠（比二次多项式更不可靠），所以 `week_reach`/`prob_qualified` 现在**严格限制在观测孕周范围 [11,29] 内**，超出范围返回 `NaN` 并打印警告，绝不隐式外推——这是本次新增的防护，v1/v2 都没有。

### 决策点 3：样条 + 随机斜率的共线问题（已发现并修复的一个真实 bug）

- **现象**：`--fast` 模式（只用 lbfgs 单一优化器）跑最终模型时未收敛，且下游 Wald 检验因协方差矩阵奇异直接崩溃（`numpy.linalg.LinAlgError: Singular matrix`）。
- **诊断**：写了一个独立诊断脚本对比"样条df5+随机斜率"、"样条df5+仅随机截距"、"样条df4+随机斜率"三种设定，发现**用完整多优化器重试（lbfgs/powell/cg/nm）时能收敛**，问题出在 `--fast` 模式为了求快只试了 lbfgs 一个优化器，这次恰好没收敛。
- **两处修复**：
  1. `wald_chi2()` 函数：协方差矩阵求逆若报奇异，改用伪逆并显式打印警告标注"请勿引用"，不再让脚本崩溃；
  2. `--fast` 模式明确定位为"开发调试用，数字不得写入论文"，默认模式（不带 `--fast`）才是四优化器完整精度。
- **仍待做**：完整精度模式下样条+随机斜率是否稳定收敛，**还没有一次完整验证过**（历史上两次完整跑都被手动中断），下一步必须先把这个跑完再谈定稿。
